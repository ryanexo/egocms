依赖流向

现在的问题不是 closuretable 没用，而是接入点不清楚

app service 业务服务通过 persistence.Transactor 开事务，但事务回调暴露 *query.Query。
→
app contract repo 接口嵌入 persistence.Repository[T]，于是 contract 也知道了 GORM Gen Query。
→
infra query/model query 和 model 变成全项目公共 API，而不是 infra 内部实现。
category/menu repo 当前树操作来自 model.ClosureTable 的 gorm-gen interface。
→
待替换方案 新写的 closuretable 使用 database/sql，需要明确 adapter 注入和事务策略。
→
目标 repo 里只调用树组件接口，不再散落 closure table SQL 或 gorm-gen template SQL。
结构风险

需要修正的点

1
根包职责过杂
persistence 同时像 facade、contract、ORM schema 容器和工具包。建议拆成明确文件和子包。
2
生成代码成为业务 API
query 是 gorm-gen 输出，但 app contract/service 直接依赖它。短期可以接受，至少要把它收进 gorm/query，标出生成边界。
3
两套路由的 closure table 并存
旧路径是 model.ClosureTable 加 gorm-gen interface，新路径是 closuretable.ClosureTable。现在不是删除新实现，而是要安排替换路径。
4
事务语义需要统一
新 closuretable 使用 *sql.DB，但现有 repo 主要使用 *gorm.DB/*query.Query。替换前要决定树操作是否共享同一个事务。
修改路线

建议按这个顺序改

1
先移动目录，不改业务语义
把 model、query、dbscope 归入 persistence/gorm。这一步主要是 import 调整。
2
把 closuretable 定义为树组件
移动到 persistence/tree/closuretable 或 persistence/closuretable，并补一个小接口：CreateSubtree、Move、DropSubtree。
3
给 category/menu adapter 注入树组件
repo 不再调用 query.CategoryContext 的生成方法，而是调用注入的 tree store。这样替换集中在 adapter 层。
4
最后移除 gorm-gen closure table template
等 category/menu 都切过去，再从 model.ClosureTable 和 cmd/gormgen 里移除旧的 interface 生成逻辑。

closuretable 接入方案

推荐的目标调用关系

CategoryRepo / MenuRepo 负责业务表更新，例如 parent_id、category、menu、seo 删除。
→
TreeStore 接口 repo 只依赖接口：创建子树、移动节点、删除子树。
→
closuretable 实现 内部封装 SQL、表名、字段名和循环移动校验。
关键决策 如果树操作必须和 GORM 写入共享事务，closuretable 不应该只持有 *sql.DB。更稳的做法是让它支持 ExecContext 级别的接口，或者提供基于 *sql.Tx/*gorm.DB session 的执行器，这样 category/menu 的业务表更新和 closure table 更新能放在同一个事务里。
注意事项

接入前建议先修的代码点

A
SQL 建表语句疑似有空格问题
CREATE TABLE%s IF NOT EXISTS 更常见的写法是 CREATE TABLE IF NOT EXISTS %s。这里接入前要先确认 MySQL/SQLite 都能跑。
B
Move 中开启事务但没有用 tx 执行 SQL
Move 里 BeginTx 后，后续仍调用 c.db.ExecContext，实际没有进入这个事务。应改成基于 tx 的执行器。
C
错误信息编码异常
ErrInvalidNode 和 ErrCircularMove 当前显示乱码，接入前要修正源码编码或直接改成稳定英文错误。
D
表名拼接需要白名单
closure table 的表名来自 option，不能用 SQL 参数占位。需要限制为可信常量，或者在构造时校验只允许字母、数字和下划线。

建议落地节奏：先移动目录并调整 import，再修 closuretable 事务和 SQL 细节，最后切 category/menu adapter。这样每一步都可回滚，且不会把结构整理和行为替换混成一次大改。
